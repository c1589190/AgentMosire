# Spec Delta

## Purpose

让运行中的子 Agent 可以请示直接父 Agent，并将需要代执行的工具调用分批提交。父子两侧按请求编号追踪裁决与执行结果，支持等待或继续工作。

## ADDED Requirements

### Requirement: 执行中查看草案和发起请求

宿主 SHALL 向有权限的子 Agent 提供查看当前草案和向直接父级提交的工具。请求可带问题、非空草案或两者，提交后新的 `Ask` 进入下一份草案。

#### Scenario: 一个回合提交两份草案

- **WHEN** 子 Agent 查看草案、提交，再产生一条 `Ask` 并再次提交
- **THEN** 两次提交有各自的请求编号，第二份草案只包含新增调用

#### Scenario: 只提问或带着草案提问

- **WHEN** 子 Agent 只发问题，或同时提交问题和草案
- **THEN** 父级收到与该请求编号对应的内容，只提问时没有生成空决策包

#### Scenario: 提交内容为空

- **WHEN** 子 Agent 提交请求时既没有有效问题也没有非空草案
- **THEN** 请求被拒绝，父级没有收到空请求

### Requirement: 父级执行及回执

父 Agent SHALL 以自己的有效权限代执行获批条目，回复 SHALL 关联同一请求及各条调用。重试 SHALL 关联已受理的请求，已执行条目不因重复请求再次产生副作用。

#### Scenario: 部分获批且父级资源仍适用

- **WHEN** 父 Agent 审核一份含多个调用的草案
- **THEN** 获批且满足父级有效权限的调用由父 Agent 执行，其余条目返回拒绝或失败理由，结果统一交回发起者

#### Scenario: 接收端收到重复请求

- **WHEN** 父级收到来自同一子 Agent、编号和内容均相同的重试
- **THEN** 父级返回已受理状态或已有回执，已经执行的条目不会重复执行

### Requirement: 两种回复等待方式

运行时 SHALL 支持暂停等待和异步两种请求方式。等待模式下，子 Agent 在回复到达前暂停。异步模式下，父级受理后子 Agent 可继续，回复按请求及会话投递。运行时 SHALL 在父级等待子任务时让新的直系子级请求可被处理。

#### Scenario: 父级正在等待子级终态

- **GIVEN** 父 Agent 正在等待某个子 Agent 结束
- **WHEN** 一个直系子 Agent 发起请求并选择暂停等待
- **THEN** 父级的等待可被该请求唤醒，父级处理完后对应子级收到回复并继续

#### Scenario: 两个子 Agent 同时发起异步请求

- **WHEN** 两个子 Agent 已收到受理回执并继续运行，父级以不同顺序处理它们
- **THEN** 各项回复只投递到对应的子 Agent 会话，子级可凭请求编号匹配结果

#### Scenario: 等待超时或请求被取消

- **WHEN** 请求超时或被取消
- **THEN** 等待方收到对应状态，结果不会被标记成已成功执行
